# External Dependency Map — Backup & Restore

## Scope

The consuming Bolts follow the Unit boundaries in [`unit-of-work.md`](../units-generation/unit-of-work.md) and edges in [`unit-of-work-dependency.md`](../units-generation/unit-of-work-dependency.md). There is no confirmed external team hand-off, named owner or ETA in the available decisions. A **Bolt** is one Construction pass for a Unit. The items below are therefore capability/configuration gates, not scheduled tasks with invented dates. “Owner” remains project/platform owner to be identified. Until each required gate is verified, limit activity to safe localhost fixtures and do not claim complete backup/restore readiness.

## Coordination rule

No asynchronous external dependency is assumed to be resolved merely because a contract or design document names it. The responsible owner must provide evidence or an explicit scope decision. Security-sensitive configuration and recovery checks are prerequisites, not post-release follow-ups.
