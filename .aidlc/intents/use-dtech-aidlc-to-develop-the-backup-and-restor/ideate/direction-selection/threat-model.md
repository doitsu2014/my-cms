# Threat model

**Purpose:** Assess Option A's localhost synthetic U1 workflow using STRIDE, including authentication, authorization, data protection and operational failure. **Status:** Proposed design analysis; mitigations are required controls, not implemented or tested claims. Residual risks await owner/architect review at the solution-direction gate. No production or real-data enablement is authorized.

**Sources:** [architecture-design.md](architecture-design.md), [decision-record.md](decision-record.md), [scope-boundary.md](scope-boundary.md), [constraints C-01–C-07](../../analyze/context-and-risk/constraints-and-assumptions.md), [risks R-01–R-12](../../analyze/context-and-risk/risk-register.md), [questions Q-01–Q-12](../../analyze/context-and-risk/open-questions.md), [AC-001–006](../../analyze/problem-framing/acceptance-criteria.md), [FEAT-01 §§5–7/10](../../../../../docs/features/backup-restore.md), and [MAP-01](../../../../knowledge/_codebase-map.md).

## Assets

| Asset | Protection objective / U1 relevance |
| --- | --- |
| Administrator identity, session/JWT and role claims | Prevent impersonation and role escalation; reuse validated auth, never trust browser roles. |
| Server-side instance registry and connection credentials | Prevent target substitution, SSRF and secret disclosure. Only configured eligible local IDs cross the API. |
| Job metadata, actor/instance associations, state/version and idempotency digests | Preserve durable truthful outcomes, authorization scope and duplicate suppression. |
| Safe audit records and correlation references | Preserve attribution and failure diagnosis without credentials or content; durable intent before effects. |
| Private fixture namespace and allocation ledger | Protect ownership and cleanup correctness, disk availability and unrelated files from deletion. Only synthetic non-sensitive bytes are permitted. |
| Existing CMS database/Auth/Storage content | Must not be captured, altered or exposed through this pilot. Metadata writes are not authorization to restore application data. |
| Browser UI/bundle, API responses, logs, traces and metrics | Prevent secondary secret/PII leakage and misleading status or capability claims. |
| Future real backup packages and keys | Sensitive deferred assets, not present in U1; separate format/protection/key decisions and verification required before introduction. |

## Trust boundaries

1. **Browser ↔ API ingress:** Browser input, IDs, roles, headers and idempotency keys are untrusted. Existing administrator JWT envelope must precede configuration/resource reads. UI route gating is not enforcement.
2. **Ingress ↔ domain application policy:** Gateway applies common security once; domain checks instance-operation/resource policy on every command/query and again at execution. An administrator role is necessary but not blanket access to every job.
3. **Domain ↔ metadata/audit database:** Durable acceptance, guarded transitions and audit commit boundaries must be designed/tested. A shared pool does not prove atomicity or table ownership.
4. **Worker/reconciler ↔ private filesystem:** Only opaque server-derived allocation paths in a feature-owned namespace; writes require durable registration, deletions require proven inactive ownership. A local process or unexpected directory entry is not automatically trusted.
5. **Server ↔ configured dependencies/secrets:** Resolve credentials server-side. Localhost scope must be enforced at deployment and registry boundaries; DNS names, Host/Origin headers or string matching alone cannot prove locality/non-production.
6. **Trusted fixture adapters ↔ deferred real-data capability:** U1 composition exposes no real capture/restore adapter. Configuration supplied by a client cannot cross this boundary; a preview is not a route to real package execution.
7. **Application ↔ diagnostics/operator:** Safe codes and references cross this boundary; raw data, credentials, paths and upstream bodies do not. Operations escalation must identify an accountable role without expanding data access.

## Entry points

- Existing login/session flow; administrator-protected instance listing, create-job and job list/read/status APIs.
- Synthetic fixture preview selection and confirmation/cancellation UI. Only predefined trusted fixture identifiers, not local paths or ZIP bytes.
- Disabled upload/preflight/restore/download request paths, including direct calls that bypass UI.
- Server configuration/instance registry, dependency startup, domain migration execution and local process/namespace ownership initialization.
- Worker dispatch, allocation, inventory reconciliation, sweep/deletion retry and restart paths.
- Browser rendering, public API errors and safe internal observability/audit outputs.
- Existing CLI skeleton: outside U1 completion, but its existing create/list errors and restore refusal must not become a bypass.

**Adversaries/faults:** Unauthenticated callers; authenticated non-admins; administrators without target/resource permission; a malicious local browser origin; guessed/replayed job identifiers; malicious request bodies; compromised credentials; local filesystem interference; accidental misconfiguration; crashes, storage exhaustion and metadata/audit outages. A fully compromised OS/database administrator can defeat local application controls; this is a residual boundary, not a claim of protection against host takeover.

## Threats

STRIDE: S = spoofing, T = tampering, R = repudiation, I = information disclosure, D = denial of service, E = elevation of privilege. IDs below are local threat identifiers, distinct from Analyze R-IDs.

| Element | STRIDE | Threat / attack vector | Mitigation required | Residual risk |
| --- | --- | --- | --- | --- |
| T-01 Authentication ingress | S, E | Forged/expired token, tampered browser roles, or writer token calls admin API directly. | Existing validated JWT actor and administrator mount; verify signature/claims/expiry against the existing auth contract, deny missing/malformed actor before config/job lookup; test the composed router, not just handlers. | Existing JWT/session implementation has not been audited or tested here; stolen valid admin credentials remain powerful. R-05. |
| T-02 Resource access | E, I | Authorized admin enumerates another actor/instance's job or guesses IDs; replay returns a protected job. | Domain checks approved administrator-instance-job policy on every list/read/create/replay/preview; filter queries server-side, return non-disclosing denial, revalidate queued execution policy. Opaque IDs supplement, never replace, checks. | Exact administrator sharing/ownership matrix pending approval (A-04); revocation semantics require review. |
| T-03 Instance selection | T, E, I | Browser submits production/remote IDs, URL/DSN/service-role key or forged environment label to redirect work/SSRF. | Strict request contract accepts configured ID only; reject unexpected connection fields; eligible server registry is local/non-production and operation-filtered; resolve secrets in server boundary; UI environment label comes from safe server metadata. No real adapter in U1. | Registry/host misconfiguration or trusted operator compromise can defeat labels; same-instance interpretation needs Q-08 confirmation. |
| T-04 Localhost ingress | S, E, D | Wildcard bind/reverse proxy exposes backup routes; malicious website uses local browser, DNS rebinding or cross-origin requests. | Review effective bind/proxy exposure; keep backup disabled unless local boundary demonstrable; restrict allowed origins/hosts using trusted configuration, not as sole authorization. Require authenticated admin and correct content type. Review existing bearer/cookie behavior; if ambient cookies authorize mutations, require CSRF controls and safe cookie settings. No broad CORS exception for locality. | Loopback does not stop other local processes or a stolen session. Exact ingress/CSRF composition requires construction tests. |
| T-05 Capability bypass | E, T | Direct real upload/restore/download call, crafted synthetic flag or existing CLI bypass reaches a real adapter. | Server-owned fixture-only composition; no runtime client switch to real capture/restore; disabled paths reject before package body processing, storage or extraction. Preserve CLI refusal; preview never enqueues mutation. Test all reachable paths with side-effect spies. | Capability wiring/config regression remains possible; fixtures do not prove future real-adapter safety. C-01/C-02/C-03. |
| T-06 Truthful status/download | T, I | Client supplies terminal state/download flag; file existence or unknown result is treated as success; incomplete fixture file is exposed by static serving. | Server-only guarded state transitions; U1 `incomplete`/`failed` terminal invariant; canonical serialization and exhaustive UI tests; no URL or static mapping; download denial regardless of requested ID/status/file presence. | Public enum expansion can break consumers; Q-01 compatibility review pending. R-06. |
| T-07 Replay and duplicate jobs | T, D, R | Rapid repeated submit, concurrent replay, reused key on changed target, or raw idempotency key leakage creates duplicate/conflicting effects. | Durable actor+operation-scoped digest, request fingerprint and uniqueness in acceptance transaction; same request retrieves authorized result, changed request conflicts. Key/metadata validation, approved finite window/retention and job/concurrency budgets; never store/log raw key. | Missing Q-05 values block enabled work; retries after approved expiry require explicit semantics, not exactly-once claims. |
| T-08 Audit and persistence | R, T | Audit unavailable but work proceeds; job accepted before commit; crash separates audit from sensitive effect. | Durable safe intent audit before effect and atomic job/idempotency acceptance where co-located; approved alternative protocol otherwise. Fail closed on unavailable audit/store; no accepted response on failed commit; uncertain commit is resolved by idempotency. | Host/DB administrator may tamper with co-located audit; independent tamper-evident logging is not implemented. Audit adapter/transaction boundary pending Q-02 review. |
| T-09 Error/telemetry leakage | I | Raw SQL/upstream response, credential/DSN, fixture accidentally containing real data, token or raw key enters UI/log/audit/metric. | Safe stable error projection; schema-limited audit; canary-secret scans of responses/bundles/logs/audit/metrics; synthetic fixtures without real content. No raw data/path/object key labels; measured counters only. | Third-party/framework logging paths require review. Synthetic canaries cannot prove absence of every leak. |
| T-10 Browser rendering | T, I, E | Error/config/fixture label rendered as HTML or executable content causes XSS and session theft. | Render labels/reasons as escaped text through existing React patterns; no raw HTML from adapter/package metadata; use existing safe auth/API helpers. Verify malicious strings in UI tests and browser security settings in review. | Broader existing admin XSS/supply-chain posture is not assessed; bearer theft remains a residual. |
| T-11 File allocation and deletion | T, E, I | Traversal, absolute path, symlink/junction/reparse-point swap, shared temp path or forged orphan causes arbitrary read/delete. | Trusted opaque allocation IDs under private owned root; no client path; least-privilege permissions. Constrain inventory/deletion to verified namespace and safe file types; prevent link following and TOCTOU in selected storage adapter; refuse ambiguous ownership, record incident. Test Windows-specific path/link/reparse behavior. | Secure filesystem semantics and exclusive ownership are not implemented/proven; local privileged attackers remain outside boundary. |
| T-12 Crash orphan/active-work race | D, T, I | Crash before ledger update loses allocation; expired but active work deleted; orphan remains indefinitely; DB outage makes sweeper guess ownership. | ADR-004 register-before-write, two-way inventory, startup fencing/exclusive namespace owner, conditional worker/cleaner state/version claims; durable discovered-orphan records and approved expiry; stop writes/deletes on DB outage; idempotent deletion, bounded retry, visible exhaustion/escalation. | Physical deletion can exceed expiry during outages; no automatic resume/exactly-once/finite cleanup SLA is claimed. Q-03 approval and tests pending. |
| T-13 Resource exhaustion | D | Oversized/repeated requests, high job concurrency, unlimited temp files, endless cleanup retry or high-cardinality metrics exhaust resources. | Reject real package bodies before domain body extraction; ingress still needs finite request/header/body/time limits. Apply approved finite job/operation/temp-byte/concurrency/retry/retention bounds, bounded inventory processing and safe metric labels; refuse missing limits. | Q-05 values pending; OS-level ingress traffic can still cause DoS. No load benchmark or SLO evidence. R-04. |
| T-14 Storage/transport confidentiality | I | World-readable private path, public static mapping, cleartext remote credentials or unmanaged keys expose content. | Only non-sensitive synthetic files in U1; private server storage/least privilege with reviewed protection. TLS on remote links; tightly local loopback exception only. Real encrypted staging/key lifecycle remains disabled pending Q-05/Q-11 and separate safety approval. | Metadata/session credentials remain sensitive even with fixtures. Real encryption/key handling is not designed or verified; localhost is not encryption. |
| T-15 Restore substitution/execution | T, E | Preview confirmation binds wrong target/package or archive-provided command is executed. | U1 confirms only labeled synthetic preview, no restore dispatch or extraction; direct restore denied. For deferred real restore, separately design server-bound package digest+target+preflight/confirmation, approved tools only, fresh policy checks and verified recovery point. Never execute archive commands. | Future confirmation binding/TOCTOU and rollback correctness remain unproven; Q-04/Q-07/Q-10 unresolved. |
| T-16 Malicious archives (deferred) | T, D, E | ZIP traversal, absolute/link/duplicate entries, decompression bomb, forged checksum or script leads to overwrite/execution/exhaustion. | U1 accepts no real package. Before later intake: approve compressed/expanded/entry limits, reject unsafe paths/links/collisions before extraction, verify manifest/checksum/version and use isolated non-mutating preflight with approved tools. | No archive validator safety claim in U1; checksums alone do not establish provenance or prevent malicious content. |
| T-17 Migration/rollback and privilege | T, D, E | Broad migration credentials, wrong schema or rollback deleting ledger ahead of files breaks isolation/cleanup evidence. | Domain-owned backup-only migrations via existing descriptors; review schema/privileges/order/upgrade tests; separate reviewed migration authority from routine worker access; disable work and preserve ledger on rollback. | Concrete privileges/migration rollback plan still need Q-02 approval. No migration executed here. |

## Authentication, authorization and protection review obligations

- Reuse the observed actor and administrator route model in [domain_interface](../../../../../apps/api/domain_interface/src/lib.rs) and the [architecture route model](../../../../../docs/architecture/software-architecture.md#route-and-authorization-model); inspect and test actual composed authentication before claiming enforcement. Frontend `AdminOnlyRoute` provides UX only.
- Owner/architect must approve the administrator-instance-job policy and actor revocation behavior. No implicit permission based on guessed ID, loopback origin, OS access or job creator alone.
- Keep secrets in the server boundary. Test safe response/audit/log/metric projection using dummy canaries, never real secrets. Do not expand existing production data access for a fixture pilot.
- Approve fixture storage/provider protection and applicable finite limits before lifecycle construction. If encryption/key policy is required for the selected storage, settle it before use; synthetic-only scope does not waive credential/metadata confidentiality.
- Q-01/Q-02/Q-03 are proposed resolutions in principle, not closed security findings. Required explicit written owner/architect approvals remain missing. Q-05/Q-06 owner decisions are pending; no example value becomes a configured default.

## Residual risks and gate disposition

**No residual risk is accepted by this worker.** Owner/architect must review T-01–T-17, explicit resource policy, enum compatibility, database-dependent cleanup availability, platform-safe filesystem behavior and the danger of mistaking synthetic workflow completion for recovery readiness. Operations must own visible cleanup failure escalation and provide finite policy inputs. The conductor owns any gate recommendation/report; direction approval does not approve unspecified limits, enable real staging or authorize production restore.

Q-04 supported Supabase recovery remains open. Real-data staging requires separately reviewed/tested cleanup and protection plus enablement approval; production additionally requires all FEAT-01 §7 conditions including approved Q-06 RPO/RTO/drills, Q-07 authority, Q-10 consistency and Q-11 keys/encryption. None is established by this threat analysis.
